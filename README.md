# Social Post Studio

A local test prototype for creating social post drafts. This version introduces accounts, credit tracking, Stripe **test-mode-only** checkout and a server-side credit gate. It is not ready for public launch or real payments. Requires Node.js 22.13 or newer.

Run `npm start` and open http://localhost:3000. Run `npm test` for automated checks. Text generation uses sample output for payment testing. Live AI requests are blocked while Stripe is in test mode, including when `OPENAI_API_KEY` is set, so test payments cannot trigger real AI charges. Never put API keys in source code, the browser, GitHub, or chat.

## Accounts, credits and Stripe test setup

Create an account in the app. Email, password hash, session identifiers, credit balances and transaction records are stored in `data/studio.sqlite`, not post content or uploaded media. Back up and protect the database; set `DATA_DIR` to a persistent, private directory if needed. This prototype is designed for a single server instance; local SQLite is not appropriate for distributed deployments. Password recovery and email verification do not exist yet. Use unique test credentials, not real customer passwords.

One credit is reserved server-side before each generation of three drafts, request for help drafting, or photo edit. A failed request normally returns the credit. A server interruption may leave a pending reservation requiring manual investigation, and a response lost after success may require support. A credit balance and purchase/usage history are tied to the account. Signup alone grants no credits. No post or image is stored in the account database.

Current proposed test prices: 1 credit $0.99, 5 credits $3.99, 15 credits $9.99, and 40 credits $19.99. These are test prices, not final customer pricing.

To test checkout, configure `STRIPE_SECRET_KEY` with a Stripe **test** secret key and `STRIPE_WEBHOOK_SECRET` with the matching test webhook signing secret. Set `PUBLIC_BASE_URL` to the app's exact origin (e.g. `http://localhost:3000`). Use Stripe CLI or a securely reachable endpoint to forward test events to `/api/stripe-webhook`; the CLI displays a temporary signing secret for that listener. Start the app after setting the variables. Never share or commit the secret keys. Stripe Checkout is hosted by Stripe; the app does not collect card details. Credits are added only after a verified paid `checkout.session.completed` event with the expected session, currency, amount, and account. Duplicate events do not add credits twice. Stripe sends test cards and instructions through its own test-mode documentation. Checkout opens in a new tab; return to the app and refresh the balance.

Only Stripe test keys are accepted. Do not modify this restriction to take live payments until HTTPS, trustworthy hosting, email verification and password recovery, production-grade identity and abuse controls, secure secrets, scalable storage, backup and restoration, payment reconciliation, chargeback/refund handling, operational monitoring, tax/legal requirements and an independent security review are complete. The tests mock Stripe; no real Stripe checkout or webhook has yet been verified. Do not expose a keyed server publicly until reviewed. Demo AI calls still consume test credits; no real money is charged by Stripe in test mode. No live AI requests are permitted in this test-mode prototype, even when an OpenAI key is configured. Photo editing needs live AI and therefore cannot be tested in this mode.

## Media and privacy

The app keeps session inputs, uploaded files and results in browser/server memory rather than saving them to the account database or app files. End session reloads and clears current browser state; closing the tab normally clears it too. Users can save or copy content themselves. In live mode, text and photos are sent to OpenAI; app controls cannot delete provider-side records or guarantee immediate deletion. Verify the provider's data retention controls and account eligibility. Videos are validated in the browser but not analyzed or edited.

Each draft has approximate previews for all platforms; the draft is written for the original selected platform and is not automatically adapted when switching previews. Users can copy text, download photos as JPG or videos in their original formats, and open a platform to publish manually. Social apps may not accept text and media together. JPGs do not contain the caption. MP4s are not transcoded or edited. Photo editing uses `OPENAI_IMAGE_MODEL` (default `gpt-image-2.5-sunburst`). Estimated progress is not provider-reported progress.

Optional `USAGE_LOGGING=true` logs token counts, model, operation and an approximate cost for Luna draft requests, but no prompts, drafts, photos or identifying account data. See the provider dashboard for billed costs. Optional `OPENAI_MODEL` defaults to `gpt-6-luna`; `MAX_UPLOAD_MB` defaults to 10 and `PORT` to 3000. The server binds to `127.0.0.1` unless `HOST` is explicitly set.
